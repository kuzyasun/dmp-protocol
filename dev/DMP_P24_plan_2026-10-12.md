# P24 Benchmark Implementation Plan

## Scope

Implement a reproducible host benchmark for the P23 C-endpoint / independent
Python-peer simulated-radio path. Compare each separately identified
RADIO-1 profile with its P03 retry-all profile for NNpsk0 and XX. Each case
creates a fresh SEC-1 association using the exact manifest bytes and digest,
issues a real service-0 freshness grant, then sends a deterministic service-2
request through two transparent relays while dropping one middle fragment.
The C endpoint completes the request and returns the result to the Python peer.

The same deterministic payload, seed, size, endpoint executable, binding,
route, loss position and schedule are used for both policies. Profile comparison
must reject differences beyond profile identity, service recovery selectors,
and the retry-policy-specific probe/status limits. No policy changes occur
inside an association.

## Measurements and limits

Report exact manifest and executable hashes; workload/payload digest; setup,
freshness-grant and warm exchange virtual time separately; host wall and CPU
time; endpoint and per-relay frame attempts, core-frame byte counts and message
type counts; dropped, repair, status, request and result counts; configured
binding-model airtime; Python allocation peak and sampled C-process RSS/high
water mark where the host exposes it. Record unavailable metrics explicitly.

Virtual time and configured airtime are simulation/model outputs. Core-frame
bytes omit the C test seam's Stream R wrapper. Host memory and CPU do not
represent MCU budgets or runtime. The tool makes no physical transport, energy,
or target resource claim.

## Acceptance

- Validate the four exact-byte manifests and their digest-index entries.
- Reject profile pairs with an unapproved behavioral difference.
- Exercise both suites, at least two payload geometries, and both recovery
  policies using the real C endpoint process and P23 relays.
- Verify equal workload inputs and result delivery, with selective repair of
  one fragment versus retry-all repair of the full fragment set.
- Unit-test report accounting and include a bounded CLI smoke in the benchmark
  test package.
- Register the focused benchmark tests in CTest, then record commands, results,
  and all measurement boundaries here and in the workboard.

## Ownership

The coordinator owns this plan, `tools/bench.py`, its CTest registration, the
P23 relay test seam needed for optional counters, and P24 workboard evidence.
Existing unrelated P23 changes remain untouched.
