# DMP Noise provider source survey

**Date:** 2026-09-26  
**Scope:** source/documentation research only; implementation remains paused.  
**Baseline:** DMP document revision 9 / SEC-1 revision 4 / BOOT_VERSION 2.  
**Decision:** no production dependency selected and no P01 capability accepted.

## Result

The inspected candidates do not establish a ready, unchanged C provider that satisfies the entire current SEC-1 contract. The maintained ESPHome Noise-C fork is the strongest C integration candidate in this survey, but two public-API limitations block acceptance: destructive handshake receive and a monotonic-only transport nonce setter. The latter prevents valid out-of-order reception even if DMP adopts abort-on-handshake-error.

`noise-protocol` with `noise-rust-crypto` is a useful comparison candidate: it exposes full handshake cloning and transport nonce/AAD access. It could sit behind a C ABI while the DMP core remains C. This adds a Rust toolchain/FFI decision and still needs RNG, erasure, panic and target-resource work. Neither route is a dependency recommendation for production yet. This is a bounded shortlist, not proof that no other implementation exists.

The owner's latest requirement is portability across MCU families. ESP32-S3 / ESP-IDF 6.x is an initial reference target, not a dependency of the core or the sole basis for provider selection.

## Required capabilities

- Exact Noise revision-34 protocol names, prologue, payloads and flight lengths from SEC-1 S2/S3. ChaChaPoly is mandatory; AESGCM and each credential mode must have explicit supported scope. General library pattern support is not DMP byte-vector evidence.
- For the current preserve-state rule: a complete bounded tentative handshake state, covering an invalid expected flight **and** a cryptographically valid read followed by failed pinned-key verification. Commit only after both checks. Copying opaque internal pointers or replaying earlier encryption is not an acceptable adapter.
- Arbitrary authenticated DMP AAD and explicit transport PN, including valid receive order `2,1` inside the replay window. Keep transmit nonce uniqueness separate from receive reordering. A method named `set_nonce` does not prove this capability.
- Cached outgoing flight bytes, no second WriteMessage call for retransmission; handshake hash, peer static key and Split access; explicit secret lifetime/erasure; finite allocation/scratch and concurrency.
- A platform entropy/error contract, software crypto without mandatory vendor acceleration, and build configurations independent of an OS, vendor SDK or PSRAM.

Base Noise deletes failed handshake state after DH/DECRYPT errors; it separately supports out-of-order transport. DMP's tentative receive is an additional integration requirement. Ordinary packet loss uses cached-flight retries under either proposed error policy. [Noise revision 34, sections 5 and 11.4](https://noiseprotocol.org/noise_rev34.html)

### Maintained Noise-C fork

The generic CMake branch creates a C library without requiring ESP-IDF. Backend selection is compile-time; libsodium is the default, with a reference-backend alternative. The IDF packaging fixes a reduced NNpsk0-only configuration; enabling XX requires an explicitly reviewed configuration rather than assuming all upstream modes survive the package switches. AES is off by default. [Build](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/CMakeLists.txt#L42), [feature defaults](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/include/noise/defines.h), [single-pattern constraints](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/src/protocol/names-single.c), [dependency manifest](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/idf_component.yml).

`noise_handshakestate_read_message` mutates the state, wipes the input buffer and sets `NOISE_ACTION_FAILED` on processing error. Its public header exposes no handshake clone/checkpoint. A successful read also precedes caller-side pin checking; copying the opaque top-level object cannot roll back its separately owned state. This fails current S3.1 through the inspected public API. [Read implementation, lines 1806–1829](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/src/protocol/handshakestate.c#L1806), [public API](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/include/noise/protocol/handshakestate.h).

Transport AEAD accepts AAD, but successful decrypt increments the internal nonce and `set_nonce` rejects any lower value. Example: after receiving PN=2, PN=1 cannot be selected although DMP may accept it. There is no public raw-key export in the inspected CipherState header to simply switch that receive state to a different AEAD API. Adopting abort-on-error does not fix this separate limitation. Any provider extension needs review and P01 evidence; do not weaken DMP's replay/reordering contract. [Decrypt and nonce setter](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/src/protocol/cipherstate.c#L377), [public cipher API](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/include/noise/protocol/cipherstate.h).

Object creation uses `calloc`, prologue setup uses `malloc`, and free wipes memory first. These are not caller-owned arena APIs. Custom entropy uses an internal `void noise_rand_bytes(...)` integration point, so recoverable RNG failure handling needs a deliberate design. The OS fallback contains POSIX/Windows dependencies and process exit; selecting CMake alone does not prove a freestanding port. Optional sodium fast paths depend on the fork's extension API and have a fallback; pin and test the actual backend rather than inferring portable performance from an ESP target. [Allocation/erasure](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/src/protocol/util.c#L136), [entropy](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/src/protocol/rand_os.c), [backend](https://github.com/esphome-libs/noise-c/blob/44722c19f7795dd409b46728712067fac87ffc53/src/backend/sodium/cipher-chachapoly.c#L31).

The original C provider has the same monotonic nonce restriction and failure transition; its age alone is not the reason for rejecting it. Its pinned name table recognizes `NoisePSK` plus `NN`, not the required `Noise_NNpsk0_...` name. Renaming the transcript is not a compatible substitute. [Original names/parser](https://github.com/rweather/noise-c/blob/cfe25410979a87391bb9ac8d4d4bef64e9f268c6/src/protocol/names.c#L76). [Original nonce API](https://github.com/rweather/noise-c/blob/cfe25410979a87391bb9ac8d4d4bef64e9f268c6/src/protocol/cipherstate.c#L499), [original receive](https://github.com/rweather/noise-c/blob/cfe25410979a87391bb9ac8d4d4bef64e9f268c6/src/protocol/handshakestate.c#L1639).

### Rust alternatives behind a possible C ABI

`noise-protocol` provides separate built-in `NNpsk0` and `XX` patterns; DMP needs those two distinct credential modes, not a combined `NNpsk0+XX` pattern. [Pattern definitions](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-protocol/src/handshakepattern.rs#L212). It implements complete HandshakeState cloning and explicitly documents cloning before a recoverable read. That permits a single provider to support both candidate policies: discard the attempt on failure, or discard a tentative clone while retaining the original. The latter can also cover caller-side pin rejection before committing the clone. `get_hash`, `get_rs` and `get_ciphers` expose the relevant outputs. This is a source-supported mechanism, not a measured memory cost or a passed DMP exchange. [Clone and state](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-protocol/src/handshakestate.rs#L11), [recovery contract](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-protocol/src/handshakestate.rs#L285), [CipherState](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-protocol/src/cipherstate.rs).

For unordered transport, consume each Split CipherState through `extract()` and use the maintained `Cipher` trait with the explicit PN/AAD. The ordinary CipherState decrypt method increments its own nonce and is not itself a packet-reordering API. [Extraction](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-protocol/src/cipherstate.rs#L161), [explicit nonce/AAD trait](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-protocol/src/traits.rs#L103). A C facade must validate lengths/state before panic-capable calls, contain failure without unwinding over the ABI, and own bounded opaque storage; no such facade is supplied or implemented here.

The protocol can exclude std/alloc and use caller-provided slices; default features must be disabled intentionally. The crypto backend wraps private/DH/cipher/hash-output material in `Sensitive`/`Zeroizing`, so a blanket claim of missing erasure is incorrect. However, queued PSKs are plain `ArrayVec<[u8;32],4>` and copied by handshake cloning. Their lifecycle and transient copies require a concrete erasure resolution before PSK mode acceptance. The stock X25519 generator uses `StaticSecret::random()` with getrandom rather than a passed RNG object; its MCU entropy/error path must be specified. A backend trait adapter may use maintained primitives, but must not reimplement Noise transitions. [Feature manifests](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-protocol/Cargo.toml), [crypto configuration](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-rust-crypto/Cargo.toml), [sensitive storage](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-rust-crypto/src/sensitive.rs), [crypto types/RNG](https://github.com/blckngm/noise-rust/blob/ffb4de5b752c88256ea31c118c0c4af5269093fc/noise-rust-crypto/src/lib.rs#L24).

Snow's inspected commit exposes stateless transport methods taking explicit nonce and additional data. Its handshake read checkpoint is internal and covers symmetric state, not a public transaction extending through application pin checks after success. No public whole-handshake Clone was found. Its documented no_std mode still needs alloc; raw secret fields/erasure need further review. An open upstream issue is a lead, not proof of every claim it makes about other libraries. [Transport API](https://github.com/mcginty/snow/blob/8ac60f51cfe3e010c84f0a454cc575ad9204fa12/src/stateless_transportstate.rs#L77), [receive/checkpoint](https://github.com/mcginty/snow/blob/8ac60f51cfe3e010c84f0a454cc575ad9204fa12/src/handshakestate.rs#L336), [no_std and audit scope](https://github.com/mcginty/snow/blob/8ac60f51cfe3e010c84f0a454cc575ad9204fa12/README.md), [erasure issue](https://github.com/mcginty/snow/issues/203).

### Other screened options

Noise* publishes generated NNpsk0 and XX C variants. Its high-level API owns device/session/peer state; session read/write do not directly accept DMP's per-packet nonce/AAD. Low-level AEAD functions have those parameters, but that alone is not an established handshake-to-transport integration. This survey does not establish a current maintained DMP-suitable adapter or transferable proof after modifications. [Project scope](https://github.com/Inria-Prosecco/noise-star/blob/ca2a3643821cb1433caf1d104f4020534b0d52c6/README.md), [XX API](https://github.com/Inria-Prosecco/noise-star/blob/ca2a3643821cb1433caf1d104f4020534b0d52c6/noise-all/api-XX/XX_25519_ChaChaPoly_SHA256/XX.h#L405), [low-level API](https://github.com/Inria-Prosecco/noise-star/blob/ca2a3643821cb1433caf1d104f4020534b0d52c6/noise-all/api-XX/XX_25519_ChaChaPoly_SHA256/Noise_XX.h).

Libhydrogen is not a drop-in SEC-1 provider: its Noise-derived key exchange uses Gimli hashing/encryption rather than DMP's fixed suites. Primitive libraries such as libsodium alone likewise do not supply the required Noise state machine. [Libhydrogen algorithm](https://github.com/jedisct1/libhydrogen/wiki/Key-exchange#algorithm)

## Portable integration direction and next decision

Keep C-facing DMP state, packets and public API independent of provider structs, SDK headers and a particular MCU's memory layout. Platform ports supply entropy and failure handling, monotonic time, credential transactions and synchronization. Software ChaChaPoly/X25519/SHA256 remains the common baseline; optional acceleration must match it byte-for-byte. Verify fixed-width encoding, alignment/endian assumptions, stack/scratch, no hot-path heap work and bounded concurrent attempts per target.

Retain two candidate provider routes for the next decision: (A) maintained C provider with reviewed upstream capability additions for tentative receive and independent receive nonce, plus allocation/entropy integration; (B) a maintained no_std Rust provider behind a narrow C ABI, with explicit target-toolchain support and erasure/RNG fixes. Neither route authorizes maintaining a private Noise implementation or silently changing the wire contract. No upstream issue/PR was posted and no dependency was installed.

Two handshake error policies can share the success path and provider. They do not inherently double the library, but require separate failure/lifetime tests and extra tentative state for preservation. The provider results qualify the earlier informal estimate: in the inspected C APIs, the missing capabilities are substantial enough that dual-policy support cannot yet be treated as a small configuration-only change. Choose policy per provisioned pair/end-to-end path, not by a local UART/radio label; do not add automatic fallback. Current S3.1 remains unchanged until an explicit owner decision.

Before a later P01 pass, require exact DMP fixtures; invalid-then-valid expected flights; valid-read/wrong-pin then valid-read; cached retransmit with one write; PN `2,1`, invalid high PN and unchanged replay state; arbitrary AAD; allocation/entropy failure; erasure of original and tentative secrets; and target-specific retained/scratch/stack figures. Add a non-Espressif freestanding compile configuration alongside the first ESP32-S3 reference. These are planned experiments, not results of this survey.
