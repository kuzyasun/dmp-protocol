## Frozen behavior and bounded design choices

- Direct TCP profile caps: 256 core bytes and 263 encoded bytes. TCP reads split/coalesce arbitrarily; writes serialize each complete Stream R envelope.
- Listener binds only `127.0.0.1`; use an ephemeral port. Per-process monotonic deadlines stay local and are never serialized or compared across peers.
- Receiver is ready before the initial empty Stream R delimiter. Decode incrementally and canonically, enforce the profile's absolute partial-candidate timeout, and discard/resynchronize as §15.2 requires.
- TCP adapter uses copy ownership with bounded queued envelopes. Rejection keeps caller ownership. Each accepted generation-tagged item gets exactly one terminal event. `strict_latest_start` is checked immediately before the first positive nonblocking socket write; a started envelope finishes in order or the connection closes with an uncertain outcome.
- Disconnect settles accepted work exactly once; reconnect creates a new generation, drops old partial envelopes and requires a fresh SEC-1 association.
- Freeze the v3 fields, mixed recovery policy and finite MTU/schedule/resource values before adapter integration. Base the mixed end-to-end envelope on the selected radio path's declared limits and `selective-32`; keep retry-all under its distinct identity. Record arithmetic as simulation-only and bind exact profile digests. This is not physical sizing evidence.
- A transparent mixed bridge uses one consistent namespace mapping and shared duplicate/cooldown/count/airtime state across its TCP/Stream R and packet interfaces. It cannot create a fresh relay budget or reset TTL when a logical fragment arrives through the other interface.
- Separate machine API byte fields from diagnostics. Default diagnostic output is limited to synthetic handles, local monotonic times, sizes, statuses, public manifest hashes and event names. It never emits full frame bytes, tokens, secrets, plaintext payloads or partial/full Noise transcripts. An identity opt-in reveals only identity fields.
