**Status:** implementation paused by the owner; documentation clarification only. A partial, unaccepted P00 host scaffold exists; no endpoint/provider implementation or passing conformance claim is implied.\
**Target repository:** `C:/projects/gemslibe/dmp-protocol` (documentation extraction is complete; production implementation follows separately).\
**Protocol baseline:** the current DMP v2 draft document revision 10, its matching SEC-1 annex, deployment profiles, and exact manifest bytes. Do not start an interoperability claim from revision 7's SELECTIVE-32 candidate text.\
**Authoritative inputs:** [main specification](../docs/DMP_v2_Device_Messaging_Protocol_Specification.md), [SEC-1](../docs/DMP_v2_Security_Profile.md), [SELECTIVE-32](../docs/DMP_v2_Selective_Recovery.md), [profiles](../docs/DMP_v2_Deployment_Profiles.md), [SAMPLE-1](../docs/DMP_v2_Reference_Application.md), design tradeoffs, public SEC-1 vectors and the two existing `dev/dmp_*security_vectors*` scripts. ## Goal and boundary

Build a portable DMP library, a small host validation/simulation suite, and explicitly named bindings and example profiles. The reusable core must not know ESP-IDF, FreeRTOS, sockets, application state, or payload codecs. No firmware extraction by copying DTrack's current DMP code into a public API: use that code only as a comparison input. DTrack, its web UI, and the companion app remain separate adoption tasks. This plan does not authorize board flashing, credential provisioning, eFuse changes, or a production rollout.

The implementation target is the single revision 10 contract referenced above. In particular, SELECTIVE-32 is an opt-in, explicitly manifested recovery mode for bounded SEC-1 reliable unicast fragmentation, with TYPE 8 `FRAG_STATUS`, a four-byte little-endian missing mask, up to 32 fragments, a separate feedback SEQ, and a same-association protected `REPLY_TO` containing only the original sender's SEQ. ACK remains final accepted-message receipt. Implement the exact revision 10 rules for feedback timing, ordering, deadlines, eviction and expiry; do not infer them from revision 7's informative proposal. Fail profile validation if any needed limit or return opportunity is unspecified. Do not add other crypto modes, generic negotiation, dynamic routing, group security, or bulk object protocols to complete this milestone.

## Proposed repository layout and ownership

| Area | Responsibility and boundary |
|---|---|
| `include/dmp/`, `src/core/` | Stable C-facing types; canonical ULEB, header/extension parser, encoder, role validation, payload descriptors, bounded frame views. Parsing has no network or application side effects. |
| `src/integrity/`, `src/stream/` | CRC32C; Stream L and Stream R/COBS framing. Stream decoders own bounded caller-supplied frame buffers and report resynchronization distinctly from DMP acceptance. |
| `src/identity/`, `src/reliability/`, `src/reassembly/` | Full message identity, generation-safe contexts, stop-and-wait exchange records, ACK/result retention, fixed-stride reassembly, and revision 10 selective recovery state. These modules receive time and storage from the caller. |
| `src/security/` | SEC-1 state machine, handshake, replay, AEAD framing, authorization/freshness and rotation. Separate reviewed standard Noise engine, existing primitive backend, fallible platform entropy and trusted credential/policy ports. A controlled fork/C port is eligible under SEC-1 S1; no novel primitives or ad-hoc KDF. |
| `src/mesh/` | Optional forwarding policy for specified static routes and bounded flooding; never decrypts transparent traffic or changes authenticated immutable headers. |
| `bindings/` | Separate named UART Stream R, BLE, radio, UDP or WebSocket adapters only when their framing/MTU/completion contracts are specified. No binding is silently enabled by core compilation. |
| `profiles/`, `examples/` | Machine-readable deployment manifests, offline validator, and a minimal application using service 1. Profile-specific schemas and sample processing remain outside `libdmp`. |
| `tests/`, `tools/`, `dev/`, `docs/` | Golden/negative vectors, state-machine and fuzz tests, deterministic network simulator, diagnostic decoder, benchmark harness, development scripts and normative documents. Development tooling never becomes an endpoint parser by accident. |

Milestone 0 confirms the initial host/toolchain and intended embedded targets, creates the minimal build/test scaffold, and proves the capabilities of a candidate production crypto provider before handshake budgets are frozen. Record the tested provider revision, license, supported suites, target constraints and resource evidence; any later provider/version change must repeat that gate. This plan selects no particular provider. Keep public headers and optional module compile switches explicit. Preserve the repository license and review dependency licensing before distributing an implementation.

## API and memory contract

Expose distinct operations for structural parse, authenticated acceptance, outgoing logical message creation, transport-send completion, and polling timers. A parsed frame view borrows input bytes only until the caller releases or reuses that input; it never implies authenticated plaintext. Accepted-message delivery gets a separately scoped payload view or a documented copy. Return structured outcomes for malformed, unsupported, integrity failure, authentication failure, missing context, incomplete, duplicate, quota exhausted, deadline expired, accepted, locally transmitted, peer receipt, and application result. Wire ERR generation is a policy decision after a valid identity/return path, not a default parser reaction.

Sessions and arenas are caller owned. Admission computes and reserves finite space before accepting a message or starting a handshake. Set explicit caps for peers, pending attempts, association/replay state, sender storage, accepted/result/correlation caches, queues, assemblies, diagnostic records, and control reserves. Reassembly may copy into a caller-provided assembly pool; no allocation in encode/decode, sampling, retry, or receive hot paths. Retain outgoing immutable plaintext/slices until final receipt or expiry; fresh protected retries allocate fresh PN and re-encrypt. Transport callbacks must define whether they copy or borrow each send buffer, when completion releases it, and what cancellation means. A TX-busy or asynchronous completion path must never outlive or mutate a borrowed frame buffer. Serialize PN allocation, replay marking and acceptance under concurrent callers. Inject monotonic time, entropy, send completion, credential store transactions, trust decisions and authorization as explicit ports. Destroy volatile association keys/counters/replay state together on restart or uncertainty.

The engine boundary must specify size/alignment for each enabled build, initialization/destruction and storage ownership, maximum concurrent operations and separate retained/scratch limits. Bounded fallible setup allocation is permitted; do not silently expand the hot-path prohibition into a universal heap ban. Public DMP headers contain no provider structs or SDK headers; compile-time provider binding is sufficient. Entropy, storage and crypto failures have explicit outcomes, with no process exit or fallback RNG. Define exactly which buffers may be modified in place, partial-output validity on failure and erasure/completion ownership. Immutable cached flights must survive a provider that mutates its receive buffer. Never dispatch tentative plaintext before AEAD and SEC-1 authorization succeed.

Expose one logical receive/post-check/accept boundary, covering decrypted payload/CID and pin checks before generating the next flight. The initial implementation owns one disposable engine state; abort invalidates its generation and safely cleans pending work. A future preserve extension may add bounded tentative storage without rolling back time/work/error counters. OOB waiting uses retained candidate data, not a monopolized shared scratch slot. Neither the exact ABI nor universal backend compatibility is fixed here. Split may produce opaque direction-specific PN/AAD contexts; raw-key export and a particular nonce setter are not requirements.

## Profile validator and example application

Make the manifest validator an offline tool and a startup gate using the same field rules. It must verify document/profile/binding revisions and exact SEC-1 profile digest; service IDs, schemas, security/ACL/freshness policy; identity and epoch source; path MTU including largest fragment index and worst allowed PN width; frame/message/fragment/assembly/queue/handshake budgets; sender/result/dedup/tombstone retention; reassembly and absolute transfer horizon inequalities; return slots; retry/repair/probe and relay airtime budgets; and adapter buffer ownership. Reject missing required fields, impossible ceilings, SELECTIVE-32 without SEC-1 or a return opportunity, and an MTU that cannot carry a permitted final fragment or protected feedback. Never silently downgrade a failed secure profile to plaintext or retry-all.

Use the already specified [SAMPLE-1 contract](../docs/DMP_v2_Reference_Application.md) unchanged in both independent endpoints: finite sample telemetry with an application sample stream key and monotonically ordered sample counter, a read request/result, and a status result. Its document supplies exact payload encoding and limits; do not redesign the schema during implementation. Telemetry is best effort and may replace an obsolete unsent sample; stale or restarted samples cannot overwrite newer accepted state. Read/status exchanges use the declared reliable request/result behavior and idempotency rule. This example has no actuator commands, firmware update, dynamic discovery, or implicit timestamp/freshness guarantee. SEC-1 service 0 remains reserved for its defined control service; the example must not reuse it.

### Shared manifest contract and test-tool boundary

P02 must publish a versioned, implementation-independent manifest contract alongside its schema (planned `docs/DMP_Test_Manifest_Contract.md` and `profiles/schema/`). Specify encoding, field types/units, required/unknown/duplicate-field handling, cross-field constraints, exact digest input bytes and a valid/invalid interpretation corpus. This is the selected test-deployment contract, not a universal new DMP wire serialization. P03 freezes the exact common manifest bytes and expected interpreted values. The independent peer receives and independently parses those bytes under this contract; matching hashes alone does not prove matching configuration. Sharing the written schema/corpus is allowed; sharing primary parser/validator code is not.

The host harness is planned as C code linked with the actual C endpoints. Before P07, P04 freezes a bounded, versioned subprocess control/trace interface for a host executable; `tools/simulate.py` later supplies scenarios/seeds and launches that executable. Specify input bounds, virtual-time/event ordering, completion/cancellation handles, exit/error outcomes and redaction. Python does not implement DMP state machines or use wall-clock sleeps as protocol time. This small test interface does not become a public libdmp ABI.

P03 includes an early independent read-only review of the manifest contract, COBS boundary vectors and protected/full reference rules from normative inputs. Record ambiguities before P04 freezes interfaces. This provides early specification feedback without claiming an independent endpoint already exists or bypassing P20/P21 acceptance. Optional earlier peer/vector coding is a scheduling change, not a prerequisite for correctness; the dependency board remains authoritative.

## Implementation milestones and acceptance gates

0. **Build scaffold and crypto feasibility gate.** Confirm targets and create the minimal runner plus a bounded provider experiment after implementation authorization. Demonstrate both NNpsk0 and XX with ChaChaPoly in the comparison; AESGCM has separate optional scope. Match exact prologue/flights/hash/Split, abort-first cleanup after admitted read/post-read failure, explicit unordered receive PN/AAD and cached retransmission without another encryption. Contrast conflicting/structurally invalid candidates (preserve the attempt) with invalid expected crypto/pin/payload (abort it); a later authentic continuation cannot resume the latter. Verify fresh scheduled establishment under unreset episode/global budgets. Record engine/backend revisions, features, licenses, patch provenance, fallible entropy, low-order X25519 rejection and secret lifetimes. Bound retained state, scratch, work and concurrency on declared targets before freezing budgets. No clone is required. An incompatible candidate fails the gate; reviewed standard-core changes must pass the same gate. The existing generator is not a production-provider feasibility test.
1. **Manifest schema and minimum validator.** Depends on 0. Record normative document hashes; define a versioned manifest representation with exact digest input bytes, and implement the minimal offline schema/constraint validator now. Complete one direct Stream R test manifest and one named simulated-radio packet manifest using declared model MTU, forward/return timing, identity, ACL and finite resource budgets informed by step 0. Simulation values are test parameters, not physical BLE/LoRa evidence; real bindings get separately validated instances in step 6. Also define the test-only `DMP-test/TEST-RADIO-RETRY-ALL/1` family and manifest: the same simulated radio binding/path, SEC-1 policy, workload ceilings, MTU, schedules and common limits/deadlines as the RADIO-1 test instance, with retry-all fixed for the compared service. This has its own profile identity and exact manifest digest; it is never a RADIO-1 downgrade. Use SAMPLE-1 as specified. Acceptance: positive manifests and digest fixtures pass; deliberately missing or contradictory fields and retry-all under a RADIO-1 identity fail. The complete selected recovery timing/retention constraints must already be expressible and checked. Startup enforcement is integrated when endpoint initialization exists in steps 3–4; step 1 does not depend on a running endpoint or step 6 tooling.
2. **Core, framing and deterministic test transport.** Depends on 1. Implement canonical parser/encoder, extension role behavior, CRC32C, Stream L/R and bounded views. Build the first deterministic event/transport harness here: injected monotonic clock, seeded frame loss/reorder/duplication, bounded queues, scheduled forward/return opportunities and delayed send-completion/cancellation callbacks. It starts with clock/queue/transport self-checks and drives actual endpoint code as steps 3–5 add it; its fault injector must not contain a replacement protocol state machine. Acceptance: applicable core/framing cases in the matrix below pass, and repeated harness inputs/seeds reproduce the same event order and trace. Initialize host CI and bounded sanitizer/fuzz checks here rather than waiting for release.
3. **Identity, direct delivery and fragmentation.** Depends on 2. Add full identity/context handling, plaintext/full versus secured compact references, ACK/result retention, stop-and-wait state, fixed-stride reassembly, conflict checks, quotas and absolute deadlines. Use the step-2 harness for the relevant main §22.8 cases. Before step 4, secure-context unit cases may use explicitly test-only authenticated-context fixtures; these are not AEAD or security conformance and cannot enter production builds. Acceptance: the delivery/reassembly matrix passes with no duplicate dispatch, lifetime renewal, silent state eviction or borrowed-buffer misuse. Repeat these cases through real SEC-1 in step 4.
4. **SEC-1 integration.** Depends on 3 and the step-0 provider gate. Integrate the demonstrated provider, exact bootstrap, verification, enrollment commit and candidate-key derivation; implement AEAD/AAD and PN/replay before protected FINISH/READY and activation, then ACL/freshness, rotation and state-loss behavior. Candidate keys or committed enrollment alone never permit application traffic. Reconcile measured integrated resource use with step-1 budgets and revalidate manifests before proceeding. Acceptance: published byte fixtures for supported suites and every applicable endpoint-local S10 assertion pass in the real endpoint. Track the relay-state portion of S10 case 6 as pending for step 5 and multi-binding forwarding case 11 as pending for step 6; the authenticated reassembly portion of case 6 and local TTL/AAD checks in case 7 still pass here. These are deferred requirements, not unsupported features or completed conformance. Unsupported optional suites are rejected explicitly, not enabled merely to satisfy a fixture. Rerun delivery/context isolation through authenticated packets, including altered protected replies and result/receipt loss. Public test keys and authenticated-context stubs remain test-only.
5. **SELECTIVE-32, routed simulation and recovery vectors.** Depends on 4; uses the existing step-2 harness, extended here for relay cooldown/forwarding limits and the selected radio schedule. Implement TYPE 8 syntax, mask/reference checks, ordering, bounded repairs/probes, terminal tombstones and interactions with reliable results. Acceptance: the full recovery matrix, including all R6/R7 cases, passes against actual endpoint code; no partial dispatch, feedback storm, parallel result resend, expired-state reopening or deadline extension. 6. **Independent peer, bindings and operator tools.** Depends on 5. ### Fragmented interoperability workload

SAMPLE-1 messages are small and do not substitute for fragmentation coverage. Define a separately named **test-only** application service (ID 2 within the test manifest), with same-service replies, SEC-1 authorization and explicit retry-all or selective-32 policy per association. Send reliable opaque DATA of known deterministic bytes, constrained by the selected profile's message/MTU ceilings. For RADIO-1, choose test MTUs and lengths that exercise N=2, an intermediate N and N=32, with exact-stride and short final slices; also test refusal when N would exceed 32. DIRECT-1 tests stay within its own lower fragment ceiling. Compare complete reconstructed bytes and one acceptance callback per admitted identity, with controlled corruption/loss and the full recovery matrix. Include a transparent relay so return routing and cooldown are exercised. Public deterministic data is fixture material; it adds no production opcode, file-transfer service or change to SAMPLE-1. Freshness-control scenarios use a separately declared test authorization/policy setup and actual S7 grants, never a bypass of SEC-1.

The independent peer must also exercise reliable REQ/result interactions required by the matrix, using a test-only service contract for large request/result bodies where SAMPLE-1 cannot trigger fragmentation. Keep that exact contract in test fixtures, including result/error meanings and limits; do not change the normative SAMPLE-1 API to make a test large.

The redacted decoder is a host diagnostic tool: it may display wire version/type, bounded lengths, routing metadata, fragment geometry, security descriptor presence, and local error category. CID/identity display follows an explicit privacy setting. It must label encrypted payload opaque until an authorized, separate diagnostic context authenticates it; default output excludes secrets, plaintext payload, tokens, key material and full handshake transcripts. Simulator inputs are seeded scenarios with explicit MTU, loss/reorder/duplication, delays, sleep and return slots, peer restarts, compromised/forged frames and quota limits. Emit a replayable event trace with absolute deadlines, bytes/airtime and state high-water marks, while redacting the same sensitive fields.
