## Goal and boundary

Build a portable DMP library, a small host validation/simulation suite, and explicitly named bindings and example profiles. The reusable core must not know ESP-IDF, FreeRTOS, sockets, application state, or payload codecs. No firmware extraction by copying DTrack's current DMP code into a public API: use that code only as a comparison input. DTrack, its web UI, and the companion app remain separate adoption tasks. This plan does not authorize board flashing, credential provisioning, eFuse changes, or a production rollout.

The implementation target is the single revision 10 contract referenced above. In particular, SELECTIVE-32 is an opt-in, explicitly manifested recovery mode for bounded SEC-1 reliable unicast fragmentation, with TYPE 8 `FRAG_STATUS`, a four-byte little-endian missing mask, up to 32 fragments, a separate feedback SEQ, and a same-association protected `REPLY_TO` containing only the original sender's SEQ. ACK remains final accepted-message receipt. Implement the exact revision 10 rules for feedback timing, ordering, deadlines, eviction and expiry; do not infer them from revision 7's informative proposal. Fail profile validation if any needed limit or return opportunity is unspecified. Do not add other crypto modes, generic negotiation, dynamic routing, group security, or bulk object protocols to complete this milestone.

## API and memory contract

Expose distinct operations for structural parse, authenticated acceptance, outgoing logical message creation, transport-send completion, and polling timers. A parsed frame view borrows input bytes only until the caller releases or reuses that input; it never implies authenticated plaintext. Accepted-message delivery gets a separately scoped payload view or a documented copy. Return structured outcomes for malformed, unsupported, integrity failure, authentication failure, missing context, incomplete, duplicate, quota exhausted, deadline expired, accepted, locally transmitted, peer receipt, and application result. Wire ERR generation is a policy decision after a valid identity/return path, not a default parser reaction.

Sessions and arenas are caller owned. Admission computes and reserves finite space before accepting a message or starting a handshake. Set explicit caps for peers, pending attempts, association/replay state, sender storage, accepted/result/correlation caches, queues, assemblies, diagnostic records, and control reserves. Reassembly may copy into a caller-provided assembly pool; no allocation in encode/decode, sampling, retry, or receive hot paths. Retain outgoing immutable plaintext/slices until final receipt or expiry; fresh protected retries allocate fresh PN and re-encrypt. Transport callbacks must define whether they copy or borrow each send buffer, when completion releases it, and what cancellation means. A TX-busy or asynchronous completion path must never outlive or mutate a borrowed frame buffer. Serialize PN allocation, replay marking and acceptance under concurrent callers. Inject monotonic time, entropy, send completion, credential store transactions, trust decisions and authorization as explicit ports. Destroy volatile association keys/counters/replay state together on restart or uncertainty.

The engine boundary must specify size/alignment for each enabled build, initialization/destruction and storage ownership, maximum concurrent operations and separate retained/scratch limits. Bounded fallible setup allocation is permitted; do not silently expand the hot-path prohibition into a universal heap ban. Public DMP headers contain no provider structs or SDK headers; compile-time provider binding is sufficient. Entropy, storage and crypto failures have explicit outcomes, with no process exit or fallback RNG. Define exactly which buffers may be modified in place, partial-output validity on failure and erasure/completion ownership. Immutable cached flights must survive a provider that mutates its receive buffer. Never dispatch tentative plaintext before AEAD and SEC-1 authorization succeed.

Expose one logical receive/post-check/accept boundary, covering decrypted payload/CID and pin checks before generating the next flight. The initial implementation owns one disposable engine state; abort invalidates its generation and safely cleans pending work. A future preserve extension may add bounded tentative storage without rolling back time/work/error counters. OOB waiting uses retained candidate data, not a monopolized shared scratch slot. Neither the exact ABI nor universal backend compatibility is fixed here. Split may produce opaque direction-specific PN/AAD contexts; raw-key export and a particular nonce setter are not requirements.

Make the manifest validator an offline tool and a startup gate using the same field rules. It must verify document/profile/binding revisions and exact SEC-1 profile digest; service IDs, schemas, security/ACL/freshness policy; identity and epoch source; path MTU including largest fragment index and worst allowed PN width; frame/message/fragment/assembly/queue/handshake budgets; sender/result/dedup/tombstone retention; reassembly and absolute transfer horizon inequalities; return slots; retry/repair/probe and relay airtime budgets; and adapter buffer ownership. Telemetry is best effort and may replace an obsolete unsent sample; stale or restarted samples cannot overwrite newer accepted state. Read/status exchanges use the declared reliable request/result behavior and idempotency rule. This example has no actuator commands, firmware update, dynamic discovery, or implicit timestamp/freshness guarantee. SEC-1 service 0 remains reserved for its defined control service; the example must not reuse it.

The currently present scripts are **fixture helpers**, not a full endpoint implementation: `dev/dmp_generate_security_vectors.py` requires a supplied upstream Cacophony text vector file and Python `cryptography`; `dev/dmp_verify_security_vectors.cjs` uses Node crypto. Keep `dev/` and `docs/` as sibling directories, since both scripts resolve `../docs/DMP_v2_Security_Test_Vectors.json` relative to their own locations. The four existing combinations (two modes × two ciphers) verify selected encoding/crypto bytes; they do not establish enrollment, ACLs, replay, fragmentation, selective feedback, interoperability or live endpoint conformance. Never regenerate committed fixtures without recording upstream source/hash and reviewing the diff.

Existing commands in this repository are `node dev/dmp_verify_security_vectors.cjs` and `python dev/dmp_generate_security_vectors.py --upstream <verified-cacophony.txt>`. These are **existing script entry points**, not claims that they were run for this plan. The CMake/CTest scaffold below has passed on the recorded Windows/GCC host; this verifies the runner, not a provider or endpoint. Opt-in candidate experiments are documented in [their README](../tests/provider/README.md). Profile/simulator/benchmark commands remain **proposed interfaces**; their tools and endpoint targets do not yet exist:

```text
cmake -S . -B build/host -DDMP_BUILD_TESTS=ON
cmake --build build/host
ctest --test-dir build/host --output-on-failure
python tools/validate_profile.py profiles/<deployment-manifest>
python tools/simulate.py --scenario tests/scenarios/<case> --seed <seed>
python tools/bench.py --workload tests/workloads/<case> --manifest profiles/<deployment-manifest>
```

Extend the step-2 CI to host compilers on at least two OS/toolchain combinations, sanitizer builds where available, corpus-based parser fuzzing, deterministic state-machine scenarios, and profile rejection cases. Record every run's exact source revision, toolchain, manifest bytes/hash, provider revision, enabled modules, MTU and seed. A green fixture check is one gate, never the release gate.

Embedded regression is required from P08 onward: cross-compile the portable core and enabled modules for the initial ESP32-S3 reference using a pinned ESP-IDF 6.x toolchain in an isolated compile-only test project, record compiler/configuration hashes and linker-map text/data/BSS changes, and retain the map/size report. Also select at P00 at least one non-Espressif freestanding cross-compile configuration (for example Cortex-M or RV32) to expose vendor/OS assumptions by P08. Record its exact compiler/ABI, supported provider/backend and memory envelope before claiming that target; an example architecture name is not a tested support claim. Each additional target needs its own budgets and evidence. This is not DTrack integration, flashing, or a physical transport test. Repeat on affected core/security changes and at P12/P15/P19/P25. Check core objects/archive for direct or transitive allocator references; classify provider/setup allocation separately, and instrument host allocation calls across initialized receive/encode/retry paths to catch indirect hot-path allocation. An empty early scaffold cannot pass the future module's allocation/resource gate. Source review, symbol checks, allocation instrumentation and target maps provide complementary evidence; host memory sizes are never substituted for MCU retained/scratch/stack budgets. Mark configured but unrun CI checks pending.

For cost comparisons, use the separately identified step-1 retry-all radio and RADIO-1 manifests, revalidate their integrated budgets and require successful workload/interoperability checks in steps 5–6 first. Each run establishes a fresh SEC-1 association bound to its own exact manifest digest; never change recovery policy within a live association. Evaluate retry-all and SELECTIVE-32 under identical payloads, path schedules, loss/reordering, ACL/security mode, crypto provider, MTU, common queue limits and deadlines. Record the distinct profile IDs/digests and recovery-specific parameter differences. If no common valid workload/envelope exists, report the comparison unsupported rather than relax profile validation. Include complete SEC-1 cold establishment and any re-establishment after restart in the relevant end-to-end cost, and report warm steady-state exchanges separately. Count both directions, binding framing, feedback, probes, final receipt/results, lost/retried frames, receive-window time and measured airtime; measure peak retained RAM, CPU, latency distribution and failure/unknown outcomes. Energy claims require actual instrumentation. State security differences explicitly; do not call a plaintext/shorter-tag/untrusted-gateway path an equivalent performance win.

Require a second endpoint implementation developed independently from the published wire contract, not a second wrapper around the same core. Exchange golden and hostile vectors in both directions, compare decoded state and emitted bytes, then execute direct and selective radio scenarios with independent state machines. Record any ambiguity as a spec issue and resolve it before freezing an interoperable release. Hardware binding validation and DTrack adoption are later gates with their own board, firmware, web and mobile checks; no host-only test proves RF timing, BLE behavior, deployment security or physical operation.
